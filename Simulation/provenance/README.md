# Research Provenance Catalog

A bounded, honest implementation of `docs/NORTH_STAR.md` Section 34
("Systemic Change #25 — Create a Research Provenance System") and Section
40 ("The First Proof of the New Architecture", whose shared-substrate list
names "provenance" and "research layer" explicitly), scoped to exactly
what Project Truman (`Simulation/`) actually has: every behavioral
constant's provenance, already stated inline as a "MODELING ASSUMPTION" /
"RESEARCH-GROUNDED" / "PLACEHOLDER" code comment per `docs/Rules.md` #2,
plus `docs/Research.md`'s prose — consolidated into one structured,
queryable place.

**This is not new research and not new provenance claims.** Every fact in
`catalog.py` was already true and already documented somewhere in
`world/*.py`, `world/agents/*.py`, `docs/Research.md`, or `docs/Memory.md`
before this catalog existed; this package indexes it, and — via
`tests/test_provenance.py` — proves the index hasn't drifted from the real
code or the real citations.

## What's in here

- **`catalog.py`** — the `ProvenanceEntry` dataclass and the catalog itself
  (a plain `dict[str, ProvenanceEntry]`, built by calling `register()` once
  per constant, same pattern as `financial_system/bridges/registry.py`'s
  `DomainBridge`/`register_domain()`). 43 entries:
  - **28 `status="implemented"`** — every constant currently in
    `world/engine.py`, `world/agents/person.py`, `world/agents/merchant.py`
    carrying an inline provenance tag, found by grepping the real files
    (not remembered from an old commit).
  - **15 `status="proposed"`** — every provenance-labeled rule from
    `docs/Research.md` Part C's three NOT-built domain designs (fraud,
    credit, loan) — matching `financial_system/bridges/registry.py`'s
    BLOCKED status for those same three domains.
- **`report.py`** — a plain-text/Markdown query script (no dashboard, per
  `docs/Design.md`'s stated convention, same style as `stats/report.py`,
  `validation/report.py`, `financial_system/bridges/capability_report.py`).
- **`CATALOG.md`** — a Markdown export of the full catalog (generated by
  `report.py --all --markdown --save`, committed as documentation; re-run
  the command above to refresh it if `catalog.py` changes).

## Vocabulary: three categories, not seven

`provenance_type` is exactly the three real categories `Rules.md` #2 uses:
`research-grounded`, `modeling-assumption`, `placeholder`. NORTH_STAR.md
Section 37 lists a fuller seven-way vocabulary (EMPIRICALLY OBSERVED /
RESEARCH SUPPORTED / CALIBRATED / INFERRED / PLAUSIBLE / ASSUMED /
HYPOTHETICAL) — deliberately **not** adopted here. Mapping every existing
"MODELING ASSUMPTION" comment onto CALIBRATED vs. INFERRED vs. PLAUSIBLE
vs. ASSUMED would require guessing a distinction neither `Research.md` nor
`Rules.md` ever drew, which this catalog has no honest basis to draw after
the fact. This mirrors `financial_system/bridges/registry.py`'s own
decision to report only its real, demonstrated BRIDGED/BLOCKED states
rather than NORTH_STAR Section 28's aspirational five-way vocabulary — see
that module's docstring for the same reasoning applied to a different
subject.

`status` is `implemented` (real code today) or `proposed` (`Research.md`
Part C design only — not built, and per that document's own "Why not built
now" sections, not a small addition).

## Querying it

```bash
cd Simulation
python provenance/report.py                              # one line per entry, whole catalog
python provenance/report.py --research-grounded           # every research-grounded entry, with citations
python provenance/report.py --placeholders                # everything still a placeholder
python provenance/report.py --modeling-assumptions         # everything a named modeling assumption
python provenance/report.py --rejected-alternatives       # every considered-and-rejected real-world number, and why
python provenance/report.py --status proposed             # every Part C design-only entry
python provenance/report.py --show SAVINGS_SWEEP_FRACTION # the full entry for one constant
python provenance/report.py --all --markdown --save provenance/CATALOG.md   # regenerate the Markdown export
```

Or query it directly from Python:

```python
from provenance.catalog import CATALOG, get, research_grounded, placeholders, with_rejected_alternatives

get("SAVINGS_SWEEP_FRACTION")          # -> ProvenanceEntry
research_grounded()                     # -> list[ProvenanceEntry]
placeholders()
with_rejected_alternatives()
```

## Testing

`tests/test_provenance.py` (run via `python -m pytest tests/test_provenance.py -v`
from inside `Simulation/`, or `python tests/test_provenance.py` directly)
runs three real, automated checks:

1. **Location/value cross-check** — every `implemented` entry's `location`
   is read from the actual current source file at that exact line, and its
   `value` is compared (via `ast.literal_eval`, not eyeballing) against
   what's really there. The single most valuable test in this package: a
   provenance catalog that silently drifts from the real code is worse
   than no catalog.
2. **Citation verification** — every `research-grounded` entry's
   `citation_verbatim` is checked as a real string-containment test against
   the actual current text of `docs/Research.md`.
3. **Coverage** — independently re-scans `world/engine.py`,
   `world/agents/person.py`, `world/agents/merchant.py` for module-level
   constants carrying a nearby provenance tag (grouping constants that
   share one leading comment block, e.g. `INCOME_LOGNORMAL_MU`/`_SIGMA`),
   and asserts every one found has a catalog entry — a real coverage check
   against the live code, not a hardcoded list compared against itself.

## Honest limitations — what this does NOT do

- **Not a living enforcement mechanism.** This is a snapshot, hand-built by
  reading the real code and real docs once, as of `catalog.py`'s
  `VERIFIED_AT_COMMIT`. It does not run in CI, does not hook into a
  pre-commit check, and does not automatically detect a NEW "MODELING
  ASSUMPTION"-style comment added to `world/` after that commit. Test 3
  above re-scans the code at TEST TIME, so it *will* fail the next time
  someone runs the test suite after adding an untagged-in-the-catalog
  constant with a provenance tag — that's a real, useful trip-wire — but
  nothing runs that check automatically on every commit today; it is only
  as fresh as the last time `pytest` was run.
- **Does not detect an inline comment losing its tag**, or a tag being
  edited to change its meaning, without also changing the constant's
  numeric value — only the `NAME = value` line itself is cross-checked
  byte-for-byte; the prose in `source`/`notes`/`confidence_note` fields is
  copied by hand from the real files and not re-diffed automatically.
- **Does not catalog every design decision in `docs/Memory.md`'s
  provenance tables** — specifically, three Phase 2 entries (`Bank reserve
  account`, `Cross-bank transfer mechanics`, `Opening balance funding`)
  are structural/mechanism decisions with no associated named constant or
  numeric value, and no inline "MODELING ASSUMPTION"-style tag exists in
  `world/agents/bank.py` itself (verified: that file's docstrings explain
  the reasoning in prose without ever using the literal tag words) —
  excluded because this catalog's schema requires a `value` field per
  entry, and inventing one for a yes/no design choice would misrepresent
  what's actually there. Named explicitly here rather than silently
  omitted.
- **Not new research.** If a future session wants to add genuinely new
  provenance-labeled constants (e.g. building any of Part C's `proposed`
  designs for real), `catalog.py`'s `register()` function is the real
  extension point — the same three-line pattern
  `financial_system/bridges/registry.py` uses for `register_domain()` —
  but doing so honestly still requires reading the real new code/citations
  first, exactly as this catalog itself was built.
